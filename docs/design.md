# ccar-drill 設計

Anthropic の資格 **Claude Certified Architect – Foundations（CCAR-F、旧称 CCA-F）** の試験勉強用アプリ。
iPhone のホーム画面アプリ（PWA）として GitHub Pages から配る。

## 試験の形（このアプリが合わせる相手）

出どころは Anthropic の試験ガイド（Version 0.1）。数字のうち 60 問・120 分だけは第三者の情報。

| 項目 | 内容 |
|---|---|
| 形式 | 4 択・正解 1 つ。誤答は「知識や経験が不完全な人が選びそうなもの」。未回答は誤答扱いで、当て推量の減点は無い |
| 採点 | スケールスコア 100〜1000、合格 720。換算式は非公開 |
| 分野 | D1 エージェント設計とオーケストレーション 27% ／ D2 ツール設計と MCP 18% ／ D3 Claude Code の設定とワークフロー 20% ／ D4 プロンプト設計と構造化出力 20% ／ D5 コンテキスト管理と信頼性 15% |
| 細目 | 分野の下に Task Statement が 30 個（1.1〜5.6） |
| シナリオ | 6 つのうち 4 つがランダムに出る。問題はシナリオ（本番に近い状況設定）の上で問われる |

## 決めたこと

| 項目 | 決定 | 理由 |
|---|---|---|
| 配り方 | PWA（GitHub Pages、`main` → `/ccar-drill/`、`develop` → `/ccar-drill/dev/`） | guitar-drill と同じ。主な使い方は iPhone のホーム画面、オフラインで動く |
| 言語・ビルド | TypeScript + Vite + Preact | guitar-drill と同じ。問題の型（選択肢ごとの解説、Task Statement の紐付け）を型で守る |
| 言葉 | 画面と解説は日本語、**問題文と選択肢は英語** | 本番は英語。英語のまま判断できるようにする。解説で要点を日本語で押さえる |
| 問題 | **すべて自作**。試験ガイドの本文・サンプル問題は載せない | ガイドには「Confidential Need to Know」の表記がある。出題範囲の確認にだけ使う |
| 覚える単位 | 問題 1 問ごとに間隔反復。習熟は **Task Statement ごと**に集計し、分野は配点で重み付けする | 本番は 30 の細目から出る。「どの細目が穴か」が一番の情報 |
| 記録 | localStorage（キー 1 つ、版付き、値ごとに検証）＋ JSON の書き出し／読み込み | ホーム画面版は Safari と保存領域が別 |
| 開発 | Docker の `node:22-alpine`、dev ポート 8009 | dev VM の Node は 16 |
| ブランチ | feature → develop → main。作業の前に Issue、`Refs #N`／本番で `Closes #N` | guitar-drill と同じ運用 |
| 対象 | CCAR-F だけ。内容（`src/content`）と仕組みは分けておく | 上位の CCAR-P は必要になってから |

## guitar-drill から変えたところ（資格試験に合わせる）

guitar-drill は「答えが計算で決まる問題を大量に作る」アプリ。こちらは「手で書いた判断問題を少数、深く解く」アプリなので、
同じ形にはしない。

1. **問題は生成しない、書く**。問題は `src/content` のデータで、テスト（`content.test.ts`）が形を検査する
   （選択肢 4 つ・正解 1 つ・選択肢ごとの解説・Task Statement とシナリオの実在・ID の重複なし・全 Task Statement に問題がある）
2. **選択肢ごとに解説する**。正解の理由だけでなく「その誤答がなぜ選ばれがちで、どこが違うか」を書く。本番の誤答は
   「不完全な理解で選びたくなるもの」なので、誤答の解説がそのまま弱点の地図になる
3. **シナリオの文はいつでも読み返せる**。問題の上に畳んで出し、タップで広げる
4. **模擬試験**：本番と同じく 4 シナリオをランダムに選び、その問題を出す。1 問 2 分の制限時間、見直し用の旗、
   最後にまとめて採点。分野別の正答率と、配点で重み付けした正答率を出す
5. **練習**：間隔反復（期限切れ→未出題→期限前）。未出題を選ぶときは「配点 ×（1 − 習熟度）」の大きい分野から優先する
6. **合格の目安**：換算式は非公開なので点数は作らない。配点で重み付けした正答率を出し、**75% を独自の目安線**にする
   （720/1000 をそのまま 72% と読むのは根拠が無い。安全側に置く）
7. **参考**：Task Statement ごとの要点（日本語）と、出題範囲外の一覧

## 構成

```
src/
  content/     試験の内容（分野・Task Statement・シナリオ・問題・要点）。データだけ
  engine/      出題（間隔反復、練習の組み立て、模擬試験の組み立てと採点、習熟度）。DOM に触らない
  store/       記録（スキーマ、移行、検証、書き出し／読み込み）
  ui/          画面と部品
```

### 問題の形

```ts
interface Question {
  id: string;              // "s1-03" など。記録のキーなので変えない
  scenario: ScenarioId;    // "s1"〜"s6"
  tasks: TaskId[];         // ["1.1", "5.2"]。先頭が主たる Task Statement
  stem: string;            // 英語
  options: [Option, Option, Option, Option];
  answer: 0 | 1 | 2 | 3;
  point: string;           // 日本語。この問題で覚えること 1 行
}
interface Option { text: string; why: string }   // text は英語、why は日本語
```

表示のときに選択肢の順番を混ぜる（位置で覚えないように）。

### 画面

1. **ホーム**：合格の目安（重み付き正答率と 75% の線）、「今日の練習」、模擬試験、分野ごとの習熟
2. **練習**：シナリオ（畳める）→ 問題 → 回答 → 正誤と選択肢ごとの解説
3. **模擬試験**：残り時間、問題の一覧（未回答・旗）、提出 → 採点 → 1 問ずつ見直し
4. **分野**：分野 → Task Statement の一覧（習熟度）→ 要点と、その Task Statement だけの練習
5. **設定**：記録の書き出し／読み込み／消去、1 回の練習の問題数
