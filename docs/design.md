# claude-cert-drill 設計

資格の試験勉強用アプリ（最初は Claude の資格だけ。2026-11-14 に基本情報技術者試験を入れると決め、資格全般向けにした。#63）。iPhone のホーム画面アプリ（PWA）として GitHub Pages から配る。
最初に載せるのは **Claude Certified Architect – Foundations（CCAR-F、旧称 CCA-F）**。
同じ仕組みで CCAR-P・CCAO-F・CCDV-F などを足せるようにする。

## 命名規則

| もの | 形 | 例 | 決まり |
|---|---|---|---|

| 資格 | 公式の試験コードを小文字・ハイフン | `ccar-f`、`ccar-p` | 旧称（CCA-F）は表示名にだけ残す。**ID は変えない**（記録のキーになる） |
| 置き場所 | `src/exams/<資格ID>/` | `src/exams/ccar-f/` | 資格の内容はここにだけ置く。仕組み（core・ui）は資格名を知らない。足し方は [adding-an-exam.md](adding-an-exam.md) |

## CCAR-F の試験の形（このアプリが合わせる相手）

出どころは Anthropic の試験ガイド（Version 0.1）。60 問・120 分だけは第三者の情報。

| 項目 | 内容 |
|---|---|
| 形式 | 4 択・正解 1 つ。誤答は「知識や経験が不完全な人が選びそうなもの」。未回答は誤答扱いで、当て推量の減点は無い |
| 採点 | スケールスコア 100〜1000、合格 720。換算式は非公開 |
| 分野 | D1 エージェント設計とオーケストレーション 27% ／ D2 ツール設計と MCP 18% ／ D3 Claude Code の設定とワークフロー 20% ／ D4 プロンプト設計と構造化出力 20% ／ D5 コンテキスト管理と信頼性 15% |
| 細目 | 分野の下に Task Statement が 30 個（1.1〜5.6） |
| シナリオ | 6 つのうち 4 つがランダムに出る。問題はシナリオ（本番に近い状況設定）の上で問われる |

資格ごとの違い（問題数・時間・シナリオの有無・合格の目安）は資格の定義（`Exam`）に持ち、画面はそれを読む。

## 決めたこと

| 項目 | 決定 | 理由 |
|---|---|---|
| 配り方 | PWA（GitHub Pages、`main` → `/claude-cert-drill/`、`develop` → `/claude-cert-drill/dev/`） | guitar-drill と同じ。主な使い方は iPhone のホーム画面、オフラインで動く |
| 原文の言語 | 資格ごとに `lang`（英語／日本語、既定は英語。#57） | 基本情報技術者試験のように問題文が日本語の資格も載せる。日本語の資格には訳と言語の切り替えを出さない |
| 言語・ビルド | TypeScript + Vite + Preact | guitar-drill と同じ。問題の型（選択肢ごとの解説、細目の紐付け）を型で守る |
| 言葉 | 画面と解説は日本語。**問題文・選択肢・シナリオは英語が正**で、日本語訳（`translations.ja`）を持ち、英語／訳はタップ（英語だけを出し、押すか答えたら訳を出す）／併記／日本語を設定と出題画面で切り替える。既定は英語。見た目（端末に合わせる／ライト／ダーク）も設定で選ぶ | 本番は英語。英語のまま判断できるようにしつつ、理解の確認には日本語で読めるようにする（2026-11-04 にユーザーの依頼で日本語版を追加）。併記だと訳を先に読んでしまうので「訳はタップ」を足した |
| 問題 | **すべて自作**。試験ガイドの本文・サンプル問題は載せない | ガイドには「Confidential Need to Know」の表記がある。出題範囲の確認にだけ使う |
| 覚える単位 | 問題 1 問ごとに間隔反復。習熟は**細目ごと**に集計し、分野は配点で重み付けする | 本番は 30 の細目から出る。「どの細目が穴か」が一番の情報 |
| 記録 | localStorage（キー 1 つ、版付き、値ごとに検証）＋ JSON の書き出し／読み込み | ホーム画面版は Safari と保存領域が別 |
| 資格の読み込み | 資格ごとに 1 つの JS（`import()`）で、問題を回ごとに分けて後から読むことはしない（#83、2026-11-16 時点） | 科目A 1367 問で JS は 1.60MB（gzip 501KB）。`tests/measure-open.cjs` で測ると、ホーム画面版の 2 回目から（先読み済み）資格を選んでホームが出るまでは CPU そのままで 0.10 → 0.19 秒、CPU 1/2 で 0.28 → 0.38 秒、1/4 で 0.65 → 1.12 秒（343 問 → 1367 問）。差が大きいのは初めて開くとき（回線 1.6Mbps で一覧から選んで 0.9 → 3.7 秒）だけで、1 度きり。分けると、記録・模擬試験・検索・細目の画面がすべて「本文がまだ無い」状態を扱うことになり、毎日の差（1 割程度の CPU 時間）に見合わない。問題をさらに大きく足すときに測り直す |
| 開発 | Docker の `node:22-alpine`、dev ポート 8009 | dev VM の Node は 16 |
| ブランチ | feature → develop → main。作業の前に Issue、`Refs #N`／本番で `Closes #N` | guitar-drill と同じ運用 |

## guitar-drill から変えたところ（資格試験に合わせる）

guitar-drill は「答えが計算で決まる問題を大量に作る」アプリ。こちらは「手で書いた判断問題を少数、深く解く」アプリなので、
同じ形にはしない。

1. **問題は生成しない、書く**。問題は `src/exams/<資格ID>` のデータで、テスト（`exams.test.ts`）がすべての資格の形を検査する
   （選択肢 4 つ・正解 1 つ・選択肢ごとの解説・細目とシナリオの実在・ID の形と重複なし・全細目に問題がある）
2. **選択肢ごとに解説する**。正解の理由だけでなく「その誤答がなぜ選ばれがちで、どこが違うか」を書く。本番の誤答は
   「不完全な理解で選びたくなるもの」なので、誤答の解説がそのまま弱点の地図になる
3. **シナリオの文はいつでも読み返せる**。問題の上に畳んで出し、タップで広げる
4. **模擬試験**：本番と同じくシナリオをランダムに選び（CCAR-F は 4 つ）、その問題を出す。本番の問題数があれば、それをシナリオの数で
   割った数ずつ選ぶ（CCAR-F は 1 シナリオ 30 問から 15 問 × 4 ＝ 60 問）。1 問あたりの時間で制限時間を決め、
   見直し用の旗、最後にまとめて採点。分野別の正答率と、配点で重み付けした正答率を出す
5. **練習**：間隔反復（期限切れ→未出題→期限前）。期限が同じ日の問題どうしはランダムに選ぶ（#97）。未出題が残っているあいだは、回の 3 分の 1 を未出題に取っておき、復習が溜まっても新しい問題に進めるようにする（#98）。未出題を選ぶときは「配点 ×（1 − 習熟度）」の大きい分野から優先する
6. **合格の目安**：換算式は非公開なので点数は作らない。配点で重み付けした正答率を出し、**75% を独自の目安線**にする。習熟の「覚えた」は、日をあけて 2 回続けて正解し（間隔 3 日以上）、期限を間隔の分以上過ぎていない問題（#28）。勘で当たった正解は数えない（#27）。期限は日で数える（1 日以上先の期限はその日の始まりから来る。1 日の区切りは朝 4 時で、0〜4 時に解いた分は前の日。続けた日数・カレンダーも同じ区切り。#93。習熟のメーターは、濃い色＝覚えた、薄い色＝あと 1 回（覚えかけ）の 2 段。同じ日の正解は覚えたに入らないので、薄い色で進み具合を見せる。合格の目安は覚えただけで数える。#94。時刻のままだと、夜に正解して翌朝に正解しても期限前になり、覚えたに進まなかった。#90）
   （720/1000 をそのまま 72% と読むのは根拠が無い。安全側に置く）
7. **参考**：細目ごとの要点（日本語）と、出題範囲外の一覧

## 構成

層は 4 つ。向きは `app → ui → core ← exams` で、境目は `src/layers.test.ts` が見張る（#51）。

```
src/
  core/          資格に依らない基盤。Preact も画面も、core の外も読まない（将来パッケージに切り出せる単位）
    exam/          資格の型（types.ts）と図の道具（figure.ts）
    engine/        出題（間隔反復、練習と模擬試験の組み立て、採点、習熟度、検索、日付）
    store/         記録の形（schema）・操作（actions）・入れ物（createStore。保存先とキーは外から渡す）
  ui/            画面と部品（資格の名前を知らない。資格は Exam で受け取る）
  exams/         資格の中身。データだけ（core/exam だけを読む）
    index.ts       載せている資格の一覧（資格の中身を読むのはここだけ）
    ccar-f/        CCAR-F（exam.ts、questions/s1.ts…、lessons/、notes.ts、ja.ts）
  app/           このアプリの組み立て（環境、記録の実体と useData、App）
  main.tsx       入口
```

### 問題の形

```ts
interface Question {
  id: string;              // "s1-03"。記録のキーなので変えない
  scenario?: string;       // "s1"。シナリオの無い資格では無し
  tasks: string[];         // ["1.1", "5.2"]。先頭が主たる細目（集計はこれで行う）
  stem: string;            // 原文の言語（資格の lang。既定は英語）
  options: Option[];        // 2〜10 個（MIN_OPTIONS〜MAX_OPTIONS。#54・#59）。CCAR-F はすべて 4 択
  answer: number;          // 正解の位置（0 始まり）。正解は 1 つだけ（複数選択はまだ無い）
  point: string;           // 日本語。この問題で覚えること 1 行
}
type Option =
  | { text: string; why: string }               // text は原文の言語、why は日本語
  | { cells: string[]; why: string };           // 解答群の表の 1 行（問題の columns と同じ数。#60）
// stem は文 1 つか、部品（段落・コード・表・図・箇条書き）の並び。プログラムや表を含む問題に使う（#60）
```

表示のときに選択肢の順番を混ぜる（位置で覚えないように）。記号は A〜J、PC のキーは数字の 1〜9 と 0（10 個目）。
英字の A〜E でも 5 個目まで選べる（F は模擬試験の旗なので、6 個目からは数字だけ。#59）。
資格ごとに記号をア〜にし、混ぜないこともできる（`options`。#58）。公式の問題をそのまま載せる資格は、混ぜないと公式の記号と答えが合う。
問題ごとに `keepOrder` で混ぜないこともできる。記号がア〜の資格は、PC のキーは数字だけで選ぶ。

### 画面

練習・教科書の章・細目の画面は、URL の `back` に来た画面を持ち、戻るボタンはそこへ戻る（「← 細目」「← 振り返り」など。#91）。無ければ練習はホーム（振り返りから始めたら振り返り）、章は目次、細目はその分野の位置。戻り先の戻り先はたどらない（URL を入れ子にしない）。

1. **資格を選ぶ**（`#/`）：載せている資格の一覧。資格が 1 つでも出す（前回の資格は覚えておき、起動時はそこへ）
2. **ホーム**（`#/<資格>`）：合格の目安（重み付き正答率と目安線）、「今日の練習」、模擬試験、分野ごとの習熟
3. **練習**：シナリオ（畳める）→ 問題 → 回答 → 正誤と選択肢ごとの解説。1 問以上答えた回は資格ごとに 1 つ記録に残り（`Data.practices`）、ホームのカードか、同じ絞り込みで開いたときの 2 択から「続きから再開する／新しく始める」を選べる（#86。URL の `start=resume|new` で選んだ状態から開く）
4. **模擬試験**：残り時間、問題の一覧（未回答・旗）、提出 → 採点 → 1 問ずつ見直し。途中で閉じても続きから（時間は画面を開いている間だけ進む）
5. **分野**：分野 → 細目の一覧（習熟度）→ 要点と、その細目だけの練習。範囲外の一覧
6. **設定**：資格ごとに試験日・1 回の練習の問題数・問題文の言語（#85。資格ごとの値が無ければ共通の値）。見た目は全体で 1 つ。記録の書き出し／読み込み／消去。書き出した時刻（`Data.exportedAt`）を残し、書き出してから（まだなら最初に答えてから）14 日たってその後にも答えていれば、ホームに書き出しの案内を出す（「あとで」で 14 日出さない。#89）
7. **振り返り**（`#/<資格>/saved`）：「☆ 後で振り返る」の印を付けた問題と、苦手な問題（`saved/weak`。#87）を切り替えて見る。どちらもその問題だけで練習できる（`only=saved|weak`）。苦手は、覚えかけ以上（間隔 1 日以上）になってから間違えた回数（`ItemStat.lapses`）が 2 以上の問題。初見の誤答と同じ回のやり直しは数えない（つまずいただけの問題と、覚えても忘れる問題を分けるため）。覚え直しても一覧に残す。メモ（`Data.notes`。#88）のある問題も一覧にでき（`saved/notes`・`only=notes`）、メモは答えを見たあとの問題カードで書く（答える前は出さない）。書きかけは入力欄から離れたとき・画面や問題が変わるときに保存し、1 文字ずつは保存しない
